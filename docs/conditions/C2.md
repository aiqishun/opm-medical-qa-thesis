# Condition C2 — single agent with an evidence-linked OPM graph

C2 makes **one** model call per question. The inputs are the same as C1: the
question, options A–D and the fixed BM25 top-10 passages E_q. The model returns:

- `answer`: A–D or `abstain`;
- `explanation`: sentences in exactly the C1 format (`grounding`,
  `question_quote`, `passage_ids`), so that C1 and C2 explanation support can be
  compared directly (RQ1);
- `graph`: an evidence-linked OPM graph (Definition 4.1). It has objects,
  processes and states (each state has one owner object), relations typed by
  Table 4.1, `answer_element_id` and `support_path`. Every element and relation
  carries its own grounding.

The deterministic validators (`src/evidence_graph/validate.py`, the programmatic
rows of Table 4.2) run on the graph. Their results are stored in
`predictions/<qid>.json` under `extra.validation`. **There is no repair and no
retry.** A graph that fails validation is still a valid output; only a parse
failure or a schema violation makes an output invalid.

| File | Role |
| --- | --- |
| `prompts/c2/system.md`, `prompts/c2/user.md` | Prompt. The citation and grounding rules are copied verbatim from C1; the user prompt is identical to C1's |
| `schemas/c2_output.schema.json` | Strict structured-output schema |
| `configs/c2.json` | Same model settings as C1 |
| `src/agents/c2.py` | Condition module (single call + validators) |
| `src/evidence_graph/` | Grounding rules and validators, reused by C3 |
| `scripts/render_graph.py` | Mermaid export per question (`outputs/graphs/<run_id>/`) |

```bash
python3 scripts/run_condition.py --condition C2 --split pilot [--limit N]
python3 scripts/score_run.py experiments/runs/<run_id>
python3 scripts/render_graph.py experiments/runs/<run_id>
```

## Validator checks

`schema`, `unique_ids`, `endpoint_types`, `state_ownership`, `connectivity`,
`citation_validity`, `question_quotes`, `grounding_rules`. Every issue names the
element or relation concerned. `unique_ids` and `grounding_rules` were added to
the six checks in the original task; the author agreed to both.

## Interpretation decisions (agreed with the author, 2026-11-28)

1. **Effect links** are stored as process → object. This is one canonical
   direction for OPM's bidirectional effect link (Table 4.1 writes
   process ↔ object).
2. **Question findings** may be objects or states, as Section 4.2 says. A
   support path may start at either.
3. **The support path is checked without regard to direction.** OPM link types
   point in different directions: consumption is object → process, result is
   process → object, input_state is state → process, output_state is
   process → state. A causal reasoning path from a finding to the answer may
   therefore run against some links. For example, a finding is typically the
   *result* or *output state* of the disease process that is the answer, so the
   path walks back from the finding to that process. Direction stays meaningful
   through the endpoint-type check; the path check only asks whether each cited
   relation connects the two steps around it. The path alternates element,
   relation, element, …. State ownership is not a path step.
4. **Input and output states.** When a process has both input and output
   states, the owners of its input states must equal the owners of its output
   states. A process with only input states or only output states passes
   (state-specified consumption or result).

Further conventions: ownership counts as a connection for the isolated-element
check. For an abstention, `answer_element_id` is null, `support_path` is empty
and the answer-path check is not applicable.

## Known limitations

- **Combination answers.** Some questions list numbered statements and have
  options such as "I, II, IV". Definition 4.1 links the answer to a single
  element, so C2 represents such an option as one combined answer element
  (e.g. an object labelled with all three causes). The graph then cannot show
  separately how each statement is supported. This is accepted. According to
  the author's review of the evaluation set, none of the 28 thesis-v0.2 test
  questions is of this type; the pilot contains at least one.
- The validators check structure only. Whether a cited passage supports an
  element, and whether a relation is used with its OPM meaning (e.g.
  exhibition used for causation), needs a reader: the C3 Verification Agent
  or the evaluation judge.
