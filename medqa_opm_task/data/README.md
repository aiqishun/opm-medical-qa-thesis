# Data card

## Delivered inputs

| File | Records | Role | Labels visible |
| --- | ---: | --- | --- |
| `input/dev_questions.jsonl` | 100 | Development questions | No labels in the input file |
| `reference/dev_labels.jsonl` | 100 | Development reference | Yes |
| `input/test_questions.jsonl` | 100 | Hidden-label evaluation questions | No |
| `processed/cardiology_knowledge.json` | Topic knowledge | Existing OPM-style knowledge structure | Not applicable |

The build script derives the development questions from
`medqa_cardiology_llm_relevant.jsonl` using IDs recorded in
`manual_audit_llm_supervised_v1.csv`. It derives the test questions from
`medqa_cardiology_real_high_confidence.jsonl` using IDs recorded in
`manual_audit_baseline_v2.csv`.

An ID of the form `qNNNN` is the zero-based row index in the corresponding
source-version file. IDs are unique within one split. Because the two source
versions differ, use `(split, id)` as the cross-file key.

## Field dictionary

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | Stable ID within the split |
| `split` | `dev` or `test` | Evaluation split |
| `source_record_index` | integer | Zero-based source row used to establish traceability |
| `question` | string | MedQA clinical vignette and question |
| `options` | object | Multiple-choice options keyed by option letter |
| `metamap_phrases` | array of strings | Existing MetaMap-derived phrase list |
| `matched_terms` | array of strings | Terms selected by the existing candidate filter |
| `filter_confidence` | string | Existing candidate-filter confidence value |

Fields absent in a source row remain absent rather than being synthesized.

## Leakage controls

Public question files are generated by an allowlist. The following source
fields are not copied: `answer`, `answer_idx`, `explanation`, all manual test
labels and reasons, and all earlier LLM classification fields. The test gold
files and measured traces are evaluator-hidden according to `task.json`.

The records are medical-exam vignettes and do not contain project-specific
patient identifiers. This packaging step performs field-level removal; it does
not claim an independent clinical de-identification review.
